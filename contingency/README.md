# C+Lua contingency and Idriç boundary

This is a C+Lua application contingency, not an accepted full Idriç Android
application. The substantial written-chord/chart/reader/dictionary core remains
in `examples/autogenerated/chordreader/` and is compiled and tested with the
maintained Idriç compiler. Host tests do not establish Android execution.

The real `AndroidCore.idric` wrapper was checked, then rejected by the DEX
backend at `Music.parse_chord`. The first failure was inability to infer a
checked call result. The backend implementation attempt adds binder-free checked
leaf inlining, Text-result branches, nested binding type inference, and correct
Unicode DEX string encoding. A repeated full-core attempt still rejects the
parser: its binders, recursive calls, constructors and collections need a
managed runtime/lowering beyond that bounded leaf implementation. The source,
checked form, diagnostics, exact revisions and qualification commands belong in
the evidence ledger; this note alone is not qualification.

The Android candidate requires the independently compiled `AppPitch.idric` DEX.
Pitch steps and ASCII accidental normalization call that DEX through ART and a
narrow JNI boundary. `music.lua` owns the remaining contingency parsing,
spelling and chart recognition; `app.lua` owns contingency state and interaction.
Its results must match live `RegressionRows.idric` output. A missing DEX payload
fails startup rather than silently switching its operations to Lua.

`android-native/platform.c` supplies ordinary Android Views, UTF-8/UTF-16
conversion, content-URI/text import, sharing, HTTPS transport, private storage,
timers and drawing. `lua-runtime.c` only transports values and events. Neither
contains a chord parser, note-name table, musical spelling rule or application
state machine. The native View callback adapter is generated by checked Idriç
source in android-NDK and remains distinct from generic ANF lowering.

The development package is `org.isomorphisms.chordreader.dev`, independent of
the inherited `org.hollowbamboo.chordreader2`. The stable public test signer is
required; no key is generated. Original source, resources, dictionaries,
translations, license and attribution remain in place. API 19 is a build target;
an API 29 emulator or Android 14 phone does not qualify API 19 runtime behavior.

Legacy song files remain plain text, setlists contain one song filename per
line, and sharing exports the source rather than the current transposed view.
The internal versioned library is length framed in Unicode scalars and shared
with the Idriç reader model. A corrupt stored library remains untouched.

Physical MIRO A1/C67 acceptance is separate from host tests, APK checks and
emulator tests. Pending or absent evidence must remain labelled as such.
